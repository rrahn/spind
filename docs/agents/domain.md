# Domain docs

## Before exploring

Read `GLOSSARY.md` at the repo root, if present, and relevant decisions in `docs/adr/`. If `GLOSSARY-MAP.md` exists, read the glossary for the relevant context instead. If these files do not exist, proceed without flagging their absence; create them only when domain modeling resolves terminology or decisions.

## Layout

This is a single-context repo. Keep the glossary at the root and architecture decision records in `docs/adr/`.

## Vocabulary and decisions

Use glossary terms consistently in issues, proposals, and tests. If a needed term is missing, note the gap for domain modeling. If a proposal conflicts with an ADR, surface the conflict rather than silently overriding it.
